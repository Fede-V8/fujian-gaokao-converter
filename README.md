# 模考 → 高考 换算器

把模考位次按「宁德市上线率比全省低 5~7 个百分点」换算成全省等效位次和高考等效分，
并对照近三年院校专业组投档线给出「能冲 / 能稳」名单。

**在线使用**：https://fede-v8.github.io/fujian-gaokao-converter/
**数据**：2026 官方 217 组 / 2025 128 组 / 2024 109 组（福建省教育考试院公开公告）

同一个算法有两个入口：**网页版**（`docs/`，已部署到 GitHub Pages）和 **命令行版**（`score_converter.py`）。

```
docs/                       ← 静态网页，无构建步骤，直接丢到 GitHub Pages 就能跑
├── index.html              ← 按顺序加载 5 个普通 <script>（core/admissions/chart/export/ui）
├── standalone.html         ← 生成物：CSS/JS 全内联，单个文件也能跑
├── styles.css              ← 手机版式 + 深浅色主题变量
├── .nojekyll               ← GitHub Pages 用
└── js/                     ← 全部挂在 window.SC 命名空间下
    ├── core.js             ← 全部算法（含推荐逻辑）
    ├── admissions.js       ← 三年院校专业组投档线（2026×217、2025×128、2024×109）
    ├── chart.js            ← SVG 折线图（纯函数）
    ├── export.js           ← 分享长图（SVG → canvas → PNG）
    └── ui.js               ← DOM 绑定与渲染

tools/build-standalone.mjs  ← 把上面 5 个文件压成 standalone.html
score_converter.py          ← 同算法的 Python 版（批量算、出报告、写文件）
test_score_converter.py     ← 36 个 Python 测试
tests/verify.mjs            ← JS 结果 vs Python 结果对拍
tests/dom-smoke.mjs         ← 无浏览器跑一遍 UI，检查接线与交互
demo_output.txt             ← 命令行版跑三个样本的输出
conversion.svg              ← 命令行版画的曲线图
```

## 快速开始

```bash

# ① 直接双击 docs/index.html（脚本是普通 <script>，file:// 也能跑）
# ② 起个服务器，最稳：
cd docs && python3 -m http.server 8000   # 打开 http://localhost:8000

# 跑测试
python3 -m unittest -v      # 36 个 Python 测试
node tests/verify.mjs       # 58 项 JS/Python 数值对拍
node tests/dom-smoke.mjs    # 29 项界面接线与交互检查
STANDALONE=1 node tests/dom-smoke.mjs   # 同样的断言再跑一遍单文件版

# 命令行版
python3 score_converter.py --demo
```

## 怎么确认自己看的是最新版

页面最底下有一行小字：

```
数据 2026×217 / 2025×128 / 2024×109 · 构建 2026-11-15 01:05
```

如果这行不存在、或时间戳比上面的旧，就是浏览器缓存了旧脚本（脚本地址带了 `?v=` 版本号，正常部署后强刷一次即可）。

## 按钮没反应怎么办

页面顶部会出现一条黄色提示，说明脚本没跑起来。常见原因只有两个：

1. **被预览器拦了**：某些 App 内置预览、或被 `sandbox` 限制的 iframe 不允许执行脚本。
   换成浏览器打开即可。
2. **文件没跟着传上去**：`js/` 目录没上传，或路径大小写不一致。

顶栏那行字就是探测结果：脚本正常时它不出现，2 秒内没就绪它就报出来。

## 部署到 GitHub Pages

网页是纯静态的，不需要 CI、不需要 `npm install`、不需要打包。

```bash
git init && git add . && git commit -m "score converter"
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库页面：**Settings → Pages → Source 选 `Deploy from a branch` → Branch 选 `main` / 目录选 `/docs` → Save**。
大约一分钟后访问 `https://<你的用户名>.github.io/<仓库名>/`。

- `docs/.nojekyll` 已放好，避免 GitHub Pages 用 Jekyll 处理文件。
- 想放到根目录也行：把 `docs/` 里的东西挪到根目录，Source 选 `/(root)` 即可。
- 换自定义域名：在 `docs/` 下加一个 `CNAME` 文件写域名，再在 Pages 里填。

## 网页版有什么

- **手机优先版式**：单列、内容宽 680px 封顶、390px 以下也不会横向溢出。
- **随便填**：分数、位次填哪个都行。只填分数时自动「分数 → 模考位次 → 全省位次 → 等效分」，只填位次时反过来补分数。
- **多人对比**：点「＋ 加入对比」把当前成绩存进表格；支持批量粘贴（`小明 500 3100`）。
- **快速换算表**：460–500 分逐 5 分的等效结果，点一行读回输入框。
- **能上 / 能冲**：按你的省位次对照近三年院校专业组投档线（2026 官方 217 组，覆盖院校代码 1001–1194），给出冲 5 个、稳 5 个，每条带 2026/2025/2024 分数与位次差。
- **存长图**：一键把结果渲染成 720×1060 的分享卡（PNG，2 倍图）。
- **深浅色**：跟随系统，也可手动切换，记住选择。
- **分享链接**：地址栏自动带 `?score=500&rank=3100&drop=6`。

## 两个方向都能算

```
分数 ──(模考曲线反推)──▶ 模考位次 ──(×倍率)──▶ 全省位次 ──(同行同列)──▶ 等效分
位次 ──(模考曲线)────▶ 分数
```

- 只填分数：先在本地位次曲线上反解出模考位次，再换算。结果卡中间那行会把整条链路写出来，
  反推出来的那一段标「反推」。
- 分数超出锚点区间（默认 460–500 分）时按端点斜率线性外推，页面会给一行黄字提示 —— 外推段的
  误差明显更大，当参考用。
- 批量导入也支持只有分数：`小明 507`。

## 方法（四步）

1. **市上线率** = 省上线率 − 5~7 个百分点

   ```
   29.71% − 6pp = 23.71%      （不是 29.71% × 0.94，那是相对下降）
   ```

2. **模考市线名次** = 市上线率 × 模考人数

   ```
   23.71% × 15000 = 3,556 名    （官方划的是 4,600 名，宽了 1,044 名 ≈ 25.6 分）
   ```

3. **位次倍率** = 省线位次 ÷ 模考市线名次

   ```
   58019 ÷ 3556 = ×16.32        你的 3,100 名 ≈ 全省 50,582 名
   ```

4. **分数平移** = 省线分 − 模考市线分

   ```
   528 − 491.6 = +36.4          500 + 36.4 = 536.4 分
   ```

这套做法只用两条线的比例和你自己给的模考锚点，不假设分数分布。
区间（±1 个百分点）落在 532–538 分之间。

## 口径与局限

- **2026 物理类总人数 195,315、特控线 528→58,019** 已按省考试院 6·25 一分一段表核实（见下节），不再是估算值。
- **模考 15,000 人是否等于全市物理类考生**——如果只有部分学校参考，市内百分位会失真。
- **5~7 个百分点是整段结论里最大的不确定源**：每动 1 个百分点，等效分动约 3 分。
- 位次是主结果（稳），分数是派生结果（估）。结果仅供定位参考，不能替代志愿填报决策。
